# OP-XY factory preset capture checklist — firmware 1.1.21

This checklist records the completed capture of the 142 factory sound states
not supplied by the eight presets in a clean device-authored default project.
Presets are ordered by the OP-XY factory category order and then alphabetically
within each category.

Status: **completed and structurally validated on 2026-09-09**.

The existing device-authored blank baseline already supplies `shoulder`,
`boop`, `in phase`, `gaussian`, `bandpasser`, `beach bum`, `dielectric`, and
`draemy`. The remaining six Strings presets have also been captured, so this
batch intentionally contains no Strings assignments.

## Capture rules

Follow these rules exactly for every project:

1. Start from a fresh copy of the clean default project, with one pattern and
   no recorded notes on Tracks 1–8. Do not reuse a musical project.
2. Name and save the project using the exact filename shown below. The names
   `fp01.xy` through `fp18.xy` are deliberately short and sort in capture order.
3. Load the specified **factory** category and preset on each assigned track.
   Do not substitute a similarly named user or downloaded preset.
4. Do not record notes or alter synth parameters, M1–M4 controls, mixer values,
   effects, octave, track scale, pattern length, mute state, or voice settings.
5. Save once after all assignments in that project are complete.
6. For `fp18.xy`, leave Tracks 7 and 8 untouched at their defaults.
7. Copy the resulting `.xy` files back without renaming them.

Changing the active track while loading presets is expected. Playing keys to
audition is safe provided recording is off and no sequencer notes are created.

## Expected returned set

The completed capture folder should contain exactly these 18 files:

```text
fp01.xy  fp02.xy  fp03.xy  fp04.xy  fp05.xy  fp06.xy
fp07.xy  fp08.xy  fp09.xy  fp10.xy  fp11.xy  fp12.xy
fp13.xy  fp14.xy  fp15.xy  fp16.xy  fp17.xy  fp18.xy
```

Before integration, each assigned source track will be checked for one pattern,
zero notes, the expected `category/preset` identity, and a coherent decoded
track structure. A failed assignment can then be recaptured individually
without repeating the other projects.
